# Example: From UX Draft to Rendered Review

This fictional case shows the handoffs without making a prototype the source of product truth.

1. Business Architect has an approved rule that managers may restore archived projects. UX Architect drafts the entry point, confirmation, success, permission-denied, and recoverable-error paths. The owner reviews and approves that concrete journey revision before it is treated as current UX.
2. Design System defines the needed action hierarchy, semantic colors, focus state, and error treatment. A representative narrow and wide preview helps the owner judge a consequential visual direction. UI Prototyper builds a navigable candidate with synthetic projects and a simulated error, labeling the mock behavior and source revisions.
3. UI Reviewer inspects the rendered confirmation and error states at relevant wide and narrow viewports and tries the keyboard path. It finds that focus is lost after the error. The authorized coding agent fixes that implementation defect, and UI Reviewer repeats the same path before marking it rechecked.
4. A reused component in the candidate also claims that all members receive a restore notification, but no approved business artifact says this. UI Reviewer reports the unsupported claim to Mastermind and Business Architect. Neither the attractive preview nor the review report approves a new notification rule.
